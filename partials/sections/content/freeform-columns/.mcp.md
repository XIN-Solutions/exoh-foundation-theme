# Freeform Columns

## Purpose

Flexible multi-column layout (1–6 columns) with per-column HTML content and optional custom Bootstrap classes. Component name: **Freeform Columns** (`partials/sections/content/freeform-columns/`). Note: `.content.json` has `"enabled": false` — component exists but may be hidden from the CMS picker.

## When to use

- Custom column layouts not covered by other components
- Mixed HTML blocks side by side (e.g. pricing tables, comparison grids)
- Experiments requiring per-column class overrides

## When not to use

- Standard icon features — use **Showcase** or **Info Tiles**
- Text + single image — use **Text & Image**
- Markdown article body — use **Markdown Text**
- When a purpose-built component fits — prefer structured components over freeform HTML

## Key fields and constraints

### Model fields (per column, N = 1..6)

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `col{N}Content` | string (HTML) | Optional | Column body; placeholder “Column” if empty |
| `col{N}Classes` | string | Optional | Bootstrap grid classes; defaults from `config.columns` |

Columns 2–6 only render when `config.columns` requires them.

### Config fields

| Field | Type | Default | Notes |
|-------|------|---------|-------|
| `columns` | string | `four` | `one`, `two`, `three`, `four`, `five`, `six` |
| `useAltBackground` | boolean | false | |
| `spacing`, `noTopSpacing`, `noBottomSpacing` | — | `comfortable` | |

Default column classes: `one` → full width; `two` → half; `three` → thirds; `four` → quarter on large screens; etc.

## Anti-patterns

- Large unstructured HTML blobs without semantic markup
- Nested section-like layouts inside columns
- Using when **Text & Image** or **Info Tiles** would give editors better structure
- Setting `columns: six` with content in only one column

## Examples

```json
{
  "col1Content": "<h3>Plan A</h3><p>For individuals.</p>",
  "col2Content": "<h3>Plan B</h3><p>For teams.</p>",
  "config": {
    "columns": "two"
  }
}
```
